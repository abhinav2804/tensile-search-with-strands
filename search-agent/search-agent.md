# Search Agent (n8n) Guide

This folder contains the n8n workflow that turns natural language queries into fast Elasticsearch lookups via an Elastic MCP server.

## What’s included

- `N8N -  Search Agent.json` — an importable n8n workflow file.

## Prerequisites

- An n8n instance you can access (self-hosted or cloud)
- An Elastic MCP endpoint to query. You can use either:
	- A remote MCP server started automatically next to your remote ES instance by the portal, or
	- The reference `tools/mcp-server-elasticsearch` server (see that folder’s README)
- A running Elasticsearch index with your data (created via the portal upload flow)

## Import the workflow

1. Open n8n → Workflows → Import.
2. Choose file and select `N8N -  Search Agent.json`.
3. Save the imported workflow.

## Configure model and tools

Inside the imported workflow:

- Set your LLM provider/API key on the model node (e.g., Claude or OpenAI Chat model).
- Update the Elastic MCP base URL to point to your MCP server, for example:
	- Remote MCP (spawned by the portal): `http://<vm-host>:<es_port+1000>`
	- Reference server: see `tools/mcp-server-elasticsearch/README.md`

The MCP endpoints used are standard:

- `GET /health`
- `GET /capabilities`
- `POST /search` with `{ query: "...", size?: number }`
- `POST /prompt` with `{ prompt: "..." }`

## Webhook alignment with the portal (optional)

The portal has an `/ask` route that posts to an n8n webhook (default demo URL). If you want the portal’s Ask UI to use your n8n instance:

1. In n8n, copy the webhook URL generated by your workflow.
2. Update the portal configuration where the webhook is called (see `frontend/app.py` → `/ask`). Use your n8n webhook URL.

This lets users type a free-form query in the portal and have n8n orchestrate the MCP calls.

## Minimal validation

After importing and configuring:

1. Ensure you’ve indexed some data using the portal (Local or Remote).
2. Verify your MCP server’s `/health` returns `healthy`.
3. Trigger the n8n workflow with a prompt, e.g.,
	 - “Want to buy red or orange LED from Syska or better brands, under 10 wattage.”
4. Observe the MCP `/search` or `/prompt` responses and the final LLM output.

## Troubleshooting

- The MCP node fails:
	- Check the MCP base URL, that ports are reachable, and ES index name exists.
- Responses look empty:
	- Confirm your indexed fields and mapping exist; try a simpler query.
- Webhook not triggered from the portal:
	- Make sure the portal’s `/ask` is pointing to your n8n webhook URL.
