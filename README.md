# Tensile Search — Zero‑Code Full Search Stack

Index any unstructured data and, with a few words, query it with filters at Elastic speed. Zero code. Full stack. Attribute‑aware.

This repository contains a hackathon‑ready, end‑to‑end deployment that:
- Accepts raw data (CSV/JSON/…)
- Generates a smart Elasticsearch mapping from data + intended queries
- Extracts attributes via LLM prompting to power faceted/filtered search
- Spins up Elasticsearch locally or remotely on demand (Docker)
- Indexes your data and exposes a simple portal to upload/search
- Connects an MCP server for LLM‑driven search and an n8n “search agent” workflow

Even as a hackathon build, the flow is wired so you can deploy and demo quickly.


## What you’ll build at a glance

1) Upload a file and paste a few example queries in the portal.  
2) The pipeline derives a schema, extracts attributes, and prepares ES documents.  
3) Choose Local or Remote. For Remote, we SSH into a VM, run Elasticsearch in Docker, index docs, and boot an MCP server next to it.  
4) Use the Search Agent (n8n) with Elastic MCP to answer natural‑language queries with filters at speed.

## Architecture

- Frontend portal (Flask) — `frontend/app.py` renders a simple upload portal and exposes APIs (upload, health, MCP status, etc.).
- EnhancedDataPipeline — `frontend/enhanced_data_pipeline.py` parses data, generates schema, extracts attributes, and indexes to Elasticsearch.
	- Local mode: indexes into `CONFIG['es_host']` (default `http://localhost:9200`).
	- Remote mode: SSH into a VM, run `elasticsearch:8.15.0` in Docker, index data, and spin up an accompanying MCP server.
- MCP for search — `tools/mcp-server-elasticsearch` and a lightweight server generated by `frontend/mcp_integration.py` (exposes `/health`, `/search`, `/index-info`, `/capabilities`, `/prompt`).
- Search Agent — `search-agent/N8N -  Search Agent.json` n8n flow calling the Elastic MCP endpoint to answer NL queries.
- User registry (optional) — `frontend/db_registry.py` persists per‑user ES/MCP endpoints and indexed indices to an external API (`CONFIG['db_api_base']`).


## Prerequisites

- Linux/macOS with Docker installed and running
- Python 3.10+ (tested with 3.11)
- For remote mode: an SSH‑reachable VM with Docker (the code defaults to a demo VM and will look for an open ES port 9200..9299)
- Optional: Kibana (via `tools/docker-elk/`) for visualizing indices


## Quick start (local demo)

1) Prepare Python environment (in `frontend/`):

```bash
cd frontend
python3 -m venv .venv
source .venv/bin/activate
python setup.py  # creates requirements.txt, folders, and a config template if missing
pip install -r requirements.txt
```

2) Start a local Elasticsearch (any one approach):

```bash
# A) Quick ephemeral ES
docker run --rm -p 9200:9200 -e "discovery.type=single-node" -e "xpack.security.enabled=false" elasticsearch:8.15.0

# B) Use the ELK helper stack (optional)
# See tools/docker-elk/ for a compose stack with Kibana
```

3) Configure the app (edit `frontend/config.py`):

- `es_host`: `http://localhost:9200`
- `es_auth`: `None` for a local, unsecured ES (or provide `("user", "pass")`)
- `db_api_base` (optional): external registry API base if you want persistence

4) Run the portal:

```bash
cd frontend
python app.py
# Portal: http://localhost:7000/esportal
```

5) Upload a CSV/JSON. Add a few user queries (“red or orange LED under 10W”, “Syska brand”, etc.). Choose "Local" deployment. The pipeline will:

- infer a schema and attribute fields
- create `schemas/<index>-schema.json`
- create an index in local ES and bulk index all documents

6) Query via the portal or connect the Search Agent (see below).


## Remote deployment (spin up ES + MCP on a VM)

When you select "Remote" in the upload form, the pipeline will:

1) SSH to your VM, stop any existing container with the same name, and run `elasticsearch:8.15.0` on the first available port in 9200..9299.
2) Index your uploaded documents into that remote ES.
3) Build and run a tiny MCP server container bound to `ES_PORT+1000` exposing:
	 - `GET /health`, `GET /capabilities`, `GET /index-info`
	 - `POST /search` and `POST /prompt`

The app will print and open the direct URLs for both ES and MCP in your browser.

Configuration for the remote VM is read by helper classes in `frontend/enhanced_data_pipeline.py` and `frontend/mcp_integration.py`. For your environment, update the VM host/user/password referenced there or provide the same credentials in a secure manner prior to running the app. Do not commit real secrets.


## Search Agent (n8n) + Elastic MCP

- Import `search-agent/N8N -  Search Agent.json` into your n8n instance.
- Configure the Model (e.g., Claude/OpenAI) and the Elastic MCP Server base URL you launched (either from `tools/mcp-server-elasticsearch` or the remote MCP that spun up next to your ES).
- The portal’s `/ask` endpoint is wired to call an n8n webhook (defaults used for the demo). Adjust in your n8n flow if needed.

See `search-agent/search-agent.md` for a step‑by‑step import and configuration.

## Configuration guide (what to set before a real demo)

- `frontend/config.py`
	- `es_host`, `es_auth`: point to your local ES for Local mode
	- `db_api_base`: if using the external registry
	- Any cloud credentials present in the file are placeholders for hackathon use only. Replace with your values or remove if unused.
- Remote VM (for Remote mode)
	- Ensure Docker is installed on the VM and the SSH user can run Docker (sudo if needed).
	- Open ports 9200..9299 and 10200..11299 (MCP uses ES_PORT+1000) or allow the ports you expect.
	- Update the VM host/user/password referenced by the remote managers in `frontend/` code before running the app.
- n8n
	- Import the flow, set your model credentials, and the MCP base URL. If you run the built‑in MCP server on the VM, the URLs will be visible in your app logs/response.


## Troubleshooting

- Flask starts but upload fails immediately:
	- Check that `frontend/config.py` exists and `es_host` is reachable for Local mode.
- Local ES connection errors:
	- Make sure Docker is running and port 9200 is open; verify `curl http://localhost:9200`.
- Remote mode stalls/fails:
	- Verify SSH connectivity (host/user/password), that Docker is installed on the VM, and that required ports are open.
- MCP health shows unhealthy:
	- Hit the MCP `/health` URL printed by the app. If unhealthy, check the MCP container logs on the VM and confirm the ES URL/index are correct.
- n8n webhook not reached:
	- Confirm the webhook URL configured in your flow is accessible from the machine running the portal.
